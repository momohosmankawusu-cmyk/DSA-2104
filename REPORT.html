2. Introduction

The accurate evaluation of mathematical expressions is a core problem in computational theory, language interpreter architecture, and compiler engineering. In traditional mathematical discourse, expressions are formulated using infix notation, wherein binary arithmetic operators (+, -, *, /) are situated between their respective operands (e.g., 3 + 5 * 2). While intuitive for human comprehension, infix notation presents computational ambiguity because evaluation order is governed not by linear positioning, but by operator precedence, left-to-right associativity rules, and parenthetical hierarchies.

Digital computing architectures evaluate instructions sequentially and cannot resolve arbitrary infix expressions without an auxiliary memory model. The Stack abstract data type (ADT), operating under the Last-In, First-Out (LIFO) protocol, is the premier data structure for parsing and evaluating such syntactic structures.

The primary objective of this project is to implement an end-to-end Python program that:

  1. Implements an object-oriented Stack class with essential operations: push, pop, peek, is_empty, and size.
  2. Reads mathematical expressions from an input file (input.txt), in which individual expressions are delimited by separator lines (such as -----).
  3. Evaluates each mathematical expression using a two-stage stack algorithm combining Dijkstra’s Shunting-Yard infix-to-postfix transformation with a stack-based postfix evaluator.
  4. Writes the computed numerical results to an output file (output.txt), maintaining the exact layout and delimiters of the input file.

3. Data Structures Used

3.1 Detailed Description of the Stack Data Structure

A Stack is a linear collection of elements with a restricted access discipline governed strictly by the Last-In, First-Out (LIFO) principle. Under LIFO, the element most recently inserted is guaranteed to be the first element removed. Access is permitted solely at the designated summit of the structure, known as the top, while the initial insertion point is termed the base.

The formal abstract contract of a Stack defines the following fundamental operations:

  • push(item): Inserts an element onto the top of the stack. In a dynamic-array-backed implementation (such as Python's list), this runs in amortized $\mathcal{O}(1)$ time complexity.
  • pop(): Removes and returns the element currently at the top of the stack. If invoked on an empty stack, it signals a Stack Underflow exception. Operates in $\mathcal{O}(1)$ time.
  • peek(): Inspects and returns the element at the top without removing it, running in $\mathcal{O}(1)$ time.
  • is_empty(): Returns a boolean flag indicating whether the stack contains zero elements ($\mathcal{O}(1)$).
  • size(): Returns the total integer count of elements currently stored ($\mathcal{O}(1)$).

3.2 Explanation of How the Stack is Used to Evaluate Expressions

To evaluate infix expressions reliably without ambiguous grammar or backtracking, the program employs two coordinated stack instances across two consecutive stages:

Stage 1: Infix to Postfix Conversion (Dijkstra's Shunting-Yard Algorithm)
In Postfix notation (Reverse Polish Notation), operators follow their operands, eliminating all parentheses and precedence ambiguity. An Operator Stack is used to defer operators until all operands of higher precedence have been processed:

  • Operands (integers and decimals) are immediately routed to the postfix output stream.
  • When an opening parenthesis ( is encountered, it is pushed onto the Operator Stack to demarcate a nested scope.
  • When a closing parenthesis ) appears, operators are continuously popped from the Operator Stack to the output stream until the corresponding ( is encountered and removed.
  • When an arithmetic operator (+, -, *, /) arrives, operators on top of the stack having greater or equal precedence are popped to the output before the incoming operator is pushed.

Stage 2: Postfix Evaluation (Operand Stack)
The resulting postfix token sequence is evaluated linearly from left to right using an Operand Stack:

  • Whenever a numerical operand is encountered, it is pushed onto the Operand Stack.
  • Whenever an operator is encountered, the top two elements are popped: the first popped element serves as the right operand ($b$) and the second popped element serves as the left operand ($a$). The operation $a \text{ op } b$ is computed, and the result is pushed back onto the stack.
  • Upon consuming all tokens, the final remaining value atop the Operand Stack is popped as the definitive mathematical result.

3.3 Importance of Stack Data Structures in Computing

Beyond expression evaluation, stacks are indispensable across core domains of computing:

  • Function Call Stack and Execution Scopes: Modern microprocessors and programming language runtimes allocate stack frames during subroutine calls to preserve instruction pointers, return addresses, parameter bindings, and local variable scopes. This mechanism enables recursive algorithms.
  • Syntax Parsing and Abstract Syntax Trees: Compilers employ deterministic shift-reduce stack parsers (such as LR, LALR, and LL parsers) to validate grammatical correctness and assemble abstract syntax trees from source text.
  • Memory Safety and Backtracking: Depth-First Search (DFS) graph traversals, backtracking engines for constraint satisfaction, and maze-solving algorithms use stacks to store decision frontiers.
  • Software History Management: Application-level undo and redo features maintain state diffs on dedicated stacks, permitting seamless reversal of user actions.

4.3 Flowchart and Pseudocode

Algorithm 1: Infix to Postfix Conversion (Shunting-Yard)

Algorithm InfixToPostfix(tokens):
    Input: List of infix tokens
    Output: List of postfix tokens (RPN)
    
    output = empty list
    op_stack = new Stack()
    
    For each token in tokens:
        If token is a number:
            output.append(token)
        Else If token == '(':
            op_stack.push(token)
        Else If token == ')':
            While not op_stack.is_empty() and op_stack.peek() != '(':
                output.append(op_stack.pop())
            If op_stack.is_empty():
                Throw Error("Mismatched parentheses: missing '('")
            op_stack.pop()  // Discard matching '('
        Else If token in {'+', '-', '*', '/'}:
            While (not op_stack.is_empty() and op_stack.peek() != '(' and
                   Precedence(op_stack.peek()) >= Precedence(token)):
                output.append(op_stack.pop())
            op_stack.push(token)
            
    While not op_stack.is_empty():
        top = op_stack.pop()
        If top == '(' or top == ')':
            Throw Error("Mismatched parentheses")
        output.append(top)
        
    Return output

Algorithm 2: Postfix Expression Evaluation

Algorithm EvaluatePostfix(postfix_tokens):
    Input: List of postfix tokens
    Output: Evaluated numerical result
    
    val_stack = new Stack()
    
    For each token in postfix_tokens:
        If token is a number:
            val_stack.push(ParseNumber(token))
        Else If token in {'+', '-', '*', '/'}:
            If val_stack.size() < 2:
                Throw Error("Insufficient operands")
            b = val_stack.pop()  // Right operand
            a = val_stack.pop()  // Left operand
            Switch token:
                Case '+': res = a + b
                Case '-': res = a - b
                Case '*': res = a * b
                Case '/': 
                    If b == 0: Throw Error("Division by zero")
                    res = a / b
            val_stack.push(res)
            
    If val_stack.size() != 1:
        Throw Error("Malformed expression: extraneous operands")
        
    Return val_stack.pop()

Step-by-Step Mathematical Analysis of Expressions:

  • Expression 1 (3 + 5 * 2): Multiplication has higher precedence than addition. The subexpression 5 * 2 computes to 10, followed by 3 + 10 = 13. The output 13 precisely matches the assignment example.
  • Expression 2 ((8 / 4) + 7 * 2): The parentheses isolate (8 / 4), which evaluates to 2. Next, multiplication executes: 7 * 2 = 14. Finally, addition executes: 2 + 14 = 16.

Rigorous mathematical evaluation confirms that $(8 / 4) + 7 \times 2 = 2 + 14 = 16$.
